# 여행노트

비밀번호로 열고, 여행과 날짜별 일정을 직접 입력하는 웹페이지입니다.

**사이트:** https://namyikim.github.io/travel_plan/ (GitHub Pages 배포 후 접속)

- 여행명·목적지·여행 기간·동행 인원 입력
- 날짜별 시간·장소·이동·숙소·메모·예약 링크 관리
- 장소 지도 검색, 여행 및 일정 수정·삭제
- 모바일·PC에서 같은 비공개 기록 조회
- 비밀번호 잠금, 암호화 백업, 연결 파일 다운로드

## 처음 연결하기

처음 한 번만 설정합니다. **사이트를 올리는 토큰과 여행 데이터를 저장하는 토큰은 별개**입니다.

1. 데이터 저장 위치는 개인용 **`namyikim/travel-data`**로 고정되어 있습니다. 사용자 이름·저장소 이름을 사이트에 입력할 필요가 없습니다. 이 저장소가 없다면 GitHub에서 `travel-data`라는 이름으로 **비공개(Private)** 저장소를 만들고 README를 추가하세요.
2. [Fine-grained token 설정](https://github.com/settings/personal-access-tokens/new)에서 데이터 저장소만 선택하고 **Contents → Read and write** 권한을 부여합니다. 만료일도 확인하세요.
3. 사이트에서 **처음 방문했어요 · 연결 설정**을 열고 데이터용 토큰과 **8자 이상 비밀번호**만 입력합니다. 긴 구절 형태를 추천합니다. 비밀번호를 잊으면 암호화한 기록을 복구할 수 없습니다.
4. 연결 설정에서 **연결 파일 내려받기**로 `connect.json`을 받습니다. 이 파일은 토큰과 저장소 이름을 비밀번호로 암호화한 파일입니다.
5. **사이트 코드 저장소 `namyikim/travel_plan`** 루트에 암호화된 `connect.json`만 업로드합니다. GitHub 웹의 **Add file → Upload files**를 이용할 수 있습니다. 로컬 Git에서는 실수 방지용 ignore가 적용되어 있으므로 파일이 암호문인지 확인한 뒤 `git add -f connect.json`을 사용합니다.
6. Pages 재배포 후 다른 기기에서도 **비밀번호만 입력**하면 같은 여행 기록이 열립니다. 업로드 전에는 첫 화면의 **연결 파일로 열기**에서 파일을 직접 선택해도 됩니다.

여행 정보나 토큰 원문을 공개 저장소에 업로드하지 마세요. 이 프로젝트에는 기본 비밀번호나 개인 토큰이 포함되어 있지 않습니다. 개인용 설정이며 회원가입이나 다른 사용자의 저장소 입력은 제공하지 않습니다. 기존 암호화 연결 파일은 계속 사용할 수 있습니다.

## 사용법

1. 비밀번호로 여행노트를 엽니다.
2. **새 여행**을 눌러 목적지와 기간을 입력합니다.
3. 날짜를 선택하고 **일정 추가**로 시간·장소·숙소·참고 링크를 적습니다.
4. 편집 창의 **반영**은 현재 화면에 적용합니다. 상단 **변경 내용 저장**을 눌러야 다른 기기에서도 볼 수 있습니다.
5. **잠그기** 또는 페이지 새로고침 후에는 다시 비밀번호를 입력합니다.

시간은 여행지의 현지 시각을 그대로 적습니다. 자동 시차 변환은 하지 않습니다. 지도 버튼은 목적지와 장소로 Google 지도를 검색합니다.

### 저장과 충돌

기록은 비공개 저장소의 `travel-data.json`에 **암호화되어** 저장됩니다. 브라우저에는 복호화 데이터나 토큰을 영구 저장하지 않습니다. 인터넷이 끊기거나 저장이 실패해도 현재 탭에는 입력이 남지만, 페이지를 닫으면 저장하지 않은 내용은 없어집니다.

다른 기기가 먼저 저장하면 자동 덮어쓰지 않고 충돌을 알립니다. 현재 변경을 보관하려면 **연결 설정 → 암호화 백업 내려받기**를 이용한 뒤 **새로 불러오기**로 최신 내용을 확인하세요. 자동 병합은 지원하지 않습니다.

### 비밀번호·토큰 변경

- **비밀번호:** 연결 설정에서 새 비밀번호를 입력합니다. 현재 기록을 새 비밀번호로 저장하고 새 `connect.json`을 내려받습니다. 반드시 사이트 저장소의 연결 파일도 교체하세요. 다른 기기도 새 비밀번호와 새 연결 파일이 필요합니다.
- **토큰 만료/교체:** 잠금 화면의 처음 연결에서 같은 데이터 저장소·새 토큰·기존 비밀번호로 연결하고 새 연결 파일을 발급합니다.
- **백업 복구:** 암호화 백업을 비공개 데이터 저장소의 `travel-data.json`으로 교체한 뒤 그 백업에 사용한 비밀번호로 연결합니다. 현재 파일을 먼저 백업하고 복구하세요. 자동 가져오기 화면은 없습니다.
- 과거 Git 커밋의 암호문은 그대로 남습니다. 비밀번호 변경은 이미 공유된 과거 데이터·토큰의 접근 권한을 소급 철회하지 않습니다. 이전 토큰의 접근을 막으려면 GitHub에서 토큰을 폐기·교체해야 합니다.

## GitHub Pages 배포

저장소 **Settings → Pages → Build and deployment**에서 다음과 같이 설정합니다.

- Source: **Deploy from a branch**
- Branch: **main** / **/(root)**
- Save 후 Pages 배포 완료를 기다립니다.

별도 빌드나 서버는 필요하지 않습니다. Pages 설정에는 저장소 관리 권한이 필요할 수 있습니다. 코드 푸시 권한만으로 Pages 설정을 변경하지 못할 수도 있습니다.

## 구조 및 검증

| 파일 | 역할 |
| --- | --- |
| `index.html`, `style.css`, `app.js` | 한국어 반응형 화면과 입력 처리 |
| `core.js` | 날짜·링크·데이터 검증과 여행·일정 CRUD |
| `crypto.js` | PBKDF2-SHA256 600,000회, AES-256-GCM 암호화 |
| `sync.js` | 비공개 저장소 확인 및 SHA 기반 충돌 감지 |
| `session.js` | 메모리 세션, 잠금, 저장·재조회·비밀번호 변경 |
| `tests/` | 데이터·암호화·세션·API·HTML 계약 테스트 |

Node.js 22 이상에서 실행합니다. 런타임 및 테스트 패키지 설치가 필요 없습니다.

현재 배포 토큰에 Workflows 쓰기 권한이 없어 GitHub Actions 자동 테스트 설정은 포함하지 않았습니다. 아래 명령으로 같은 테스트를 실행할 수 있습니다.

```bash
npm test
```

정적 서버에서 미리 볼 수 있습니다. 암호화는 **HTTPS 또는 localhost**가 필요합니다. HTML 파일을 직접 여는 방식은 연결 파일을 불러오지 못할 수 있습니다.

```bash
python3 -m http.server 8000
```

보호 범위는 암호화된 연결·여행 데이터입니다. 공개 사이트 자체의 HTML·JavaScript는 누구나 볼 수 있습니다. 잠금 해제 중인 기기나 악성 브라우저 확장 기능에 대한 보호를 보장하지 않습니다.
